### 做了什么

- **流水线和分析器接口**：`app/analyzers/base.py` 定义冻结的输入/输出/生命周期接口；四路并行、各自超时并受整单截止约束、失败互相隔离、降级标记并入报告、汇总失败用兜底报告、进度通过轮询可见。四个分析器包和汇总都是占位实现，端到端能产出符合契约的报告（标题标「【占位】」）。
- **给其他会话的扩展点**（详见 `server/ARCHITECTURE.md`）：分析器包 `models.py` 自动建表；配置项预先声明，另有自定前缀的逃生口；`python -m app.analyzers.<包>` 命令行入口；按目录单独跑测试；不经过 HTTP 的 `open_pipeline()` / `run_check()`。
- **模拟模式**：`MOCK_MODE=1` 或 `--mock`，按 `MOCK_STEP_MS`（默认 600 毫秒）依次点亮五项，最后返回契约示例报告；健康检查返回 `mock: true`。
- **测试**：84 个，覆盖契约示例、三个接口的主路径和错误路径、模拟模式、占位分析器的完整流程、单路超时/抛异常/返回非法结果/启动失败/包导入失败时报告照常产出、任务级失败返回 200 + `failed`、遗留任务清理、过期清理、表自动创建、UTF-8 存取。测试期间禁止一切非回环网络连接。
- **文档**：`server/README.md`、`server/ARCHITECTURE.md`、`docs/android-handoff.md`、本文件。

### 做了什么

- **服务端二次脱敏** `app/redact.py`：按契约第 2 节实现，`IMPLEMENTED = True`。可以重复执行，已经是占位符的内容不会被再改。启动输出不再提示「未实现」。
- **规则集** `shared/rules.json`：版本 `2026.11.2`，69 条规则，覆盖刷单、投资、冒充客服、冒充熟人、通用话术（垫付、下载、保密、紧迫等）。另有归一化表（零宽字符、变体词）。
  - 每条规则在 `shared/rules-samples.json` 里有命中和不命中样例，两端共用。
  - 正则只用契约 4.5 允许的公共子集，测试会拒绝后行断言、命名分组、内联标志和占有量词。
  - 规则引擎 `app/rules/`：NFKC 归一化 → 删零宽字符 → 变体词替换（长词优先）→ 匹配。引文映射回原文，保证是原行的逐字子串；命中边界落在 `<AMOUNT:…>` 中间时扩到整个占位符。
- **大模型客户端** `app/llm/`：OpenAI 兼容接口，主备两个模型。
  - 要求 JSON 输出，temperature 0，关闭思考模式（通义 `enable_thinking: false`，智谱 `thinking.type: disabled`，DeepSeek 官方接口 `api.deepseek.com` 也是 `thinking.type: disabled`，按主机名判断）。其他中转站不传这个参数：ai.apiclub.top 上试过四种写法都关不掉。
  - 连接超时（默认 3 秒）短于读取超时，并且不超过剩余预算。SDK 自带重试关闭，由外层 `asyncio.wait_for` 兜底整体截止。
  - JSON 解析或校验失败时带提示重试一次，传输错误不重试，重试与首次共用同一个截止时间。
  - 每次鉴定记录一次健康状态（`/v1/health` 的 `llm` 字段）：主备任一成功就是 `ok`。
- **话术分析** `app/analyzers/script/` + 提示词 `app/prompts/script_v1.md`：
  - 聊天内容放在 `<chat_data>` 里作为数据交给模型（转义了 `</chat_data`），系统提示要求忽略其中的指令。
  - 主模型失败（超时、错误、两次输出不合格）自动切备用。`CROSS_CHECK=off` 时主模型最多用 60% 的预算，卡住时也给备用留出时间；返回前取消并等待没跑完的调用。`CROSS_CHECK=parallel` 时主备同时调用，另一方结果写进 `extras.cross_check.other`，供汇总做交叉复核。`cross_check` 每次运行时从 `ctx.settings` 读取，评测可以用 `settings.model_copy(update=...)` 切换。
  - 没有密钥、两个都失败或剩余预算不够时，只用规则并带 `llm_unavailable_rules_only`。
- **打分** `app/scoring/`（权重 `weights.yaml`）：p = sigmoid(偏置 + 意图 + 规则 + 链接 + 案例 + 深伪)，各分量有封顶。`risk_score == round(100·p)`；`suspicious` 时钳到 6–59，避免四舍五入跨档。
- **汇总** `app/summary/`：
  1. 证据逐字回查：行号错了先在对方的行里找并修正，找不到就丢弃，不参与打分。
  2. 打分。
  3. 契约第 6 节的每条硬性约束：没有证据或 high 链接不给 `high_risk`；深伪单独不给 `high_risk`；交叉复核一方 high、一方 low 时降到 `suspicious` 并加 `cross_check_disagreed`；没有大模型时最高 `suspicious`（命中黑名单的链接除外）；内容太少给 `inconclusive`；文案不出现「安全」「可以放心」。
  4. 固定模板 `templates.yaml`。大模型写的 `summary`、`next_move`、`explanation` 含「安全」「放心」等字样时换成模板；规则证据的说明来自规则标题和模板，不做这项替换。
  - 话术这一路没跑完时，汇总在本地补算规则命中。
  - 标题不再带「【占位】」。
- **测试**：新增脱敏、规则（逐条样例）、大模型客户端（21 个）、话术分析（20 个）、汇总（47 个，硬性约束每条至少一个）、「必须通过的场景」（12 个，打桩模型走完整流水线）、`RUN_LIVE=1` 才运行的真实模型场景（7 个）。

## 第 5 步：超时与降级、断网路径、启动前自检、README（已完成，真实模型和真实断网未验证）

### 做了什么

先盘点了已有的实现，只补缺口：

- **超时与降级**（第 2 步已具备，本步核对）：整单硬上限 20 秒（`CHECK_DEADLINE_S`）；各路独立超时话术 12、链接 5、案例 3、媒体 15 秒，且都受整单剩余时间约束（给汇总留出预算）。连接超时短于读取超时：大模型 `connect=min(3, 剩余)`，向量接口 `connect=min(大模型连接超时, 向量超时/2)`，链接每跳 1.5 秒，RDAP 和情报 `connect=min(1.5, 剩余)`，WHOIS 整体包在 `wait_for` 里。任何一路超时或抛异常只把那一路标成 `failed` 并加对应降级标记（超时另加 `partial_timeout`），汇总失败用兜底报告。
- **启动前自检命令** `uv run python -m app.selfcheck`（新增 `app/selfcheck.py`）：Mac 和 Windows 同一条命令，逐项打印「通过 / 失败 / 未配置 / 提示」和失败时该怎么办，退出码 0/1。
  - 公共项：配置文件、模拟模式、访问令牌、数据库实际写入、ffmpeg（P1，找不到只「提示」）、监听地址。
  - 各分析器的项通过 `selfcheck()` 钩子收集（同时跑，单个最多 30 秒，抛异常或超时变成一条「失败」，不会让自检崩掉）：话术（规则条数和版本、提示词、主备模型各发一次最小请求）、案例（案例条数、向量一致性、向量接口调用一次）、链接（数据文件、RDAP 查一次）。媒体那一路的检查项由它自己的钩子提供；它没提供 ffmpeg 项时由公共项补上。
  - 没有密钥时主备模型和向量接口显示「未配置」，算没通过，不会显示成通过。
  - 大模型的探测结果写进数据库新表 `app_state`，服务启动时读回作为 `/v1/health` 的 `llm` 初始值（契约 4.6「最近一次真实调用或启动自检的结果」）。12 小时以前的结果不用；没配置密钥那次写的是 `unknown`，会盖掉旧结果；服务运行中有真实调用后以真实调用为准。
- **监听所有网卡**时启动输出打印本机局域网地址并提醒放行防火墙（逻辑抽到 `app/netinfo.py`，自检的「监听地址」一项共用）。启动输出最后提示先跑自检。

### 提交前评审修掉的问题

对第 5 步的改动做了一轮对抗式评审，确认并修掉：

- 自检时数据库打不开（目录没权限、文件损坏）会让整条命令崩掉 → 现在变成一条「数据库 失败」和怎么办，其余各项照常打印。
- `.env` 里有不合法的值（比如 `PORT=abc`）时自检直接抛异常 → 现在逐个列出写错的变量名和怎么办，退出码 1。
- 上次自检被中断留下的探测行会让下次「数据库」误报失败 → 改成覆盖写。
- 分析器包加载失败时自检里看不出来 → 加载失败的那一路现在报一条「失败」。
- 服务运行中真实调用得到的 `llm` 状态，重启后会被更早的自检结果盖住 → 服务退出时把真实调用的结果存下来。
- 链接这一路到点时如果还卡在短链展开上、没轮到查已配置的外部情报，报告里漏了 `intel_unavailable` → 补上。
- `--host ::` 只监听 IPv6，手机用 IPv4 地址连不上，原来当成「所有网卡」处理 → 现在单独提示改用 `--host 0.0.0.0`；IPv6 地址在启动输出里加方括号。

## P1：用户反馈和规则集下发（已完成）

## P1：媒体接进主流程（已完成，真实模型的准确率和大模型路径未验证）

### 做了什么

- `main.py` 挂上 `POST /v1/media`（媒体包的路由）。成功返回 201（契约 4.1 没规定，沿用媒体包的实现）。`/v1/media` 不再受 1 MB 请求体上限：中间件对它按「三类文件上限里最大的 + 64 KiB 表单开销」卡，具体类型的上限（图片 5 MB、音频 10 MB、视频 50 MB）由路由按 `kind` 卡，超限 413 `PAYLOAD_TOO_LARGE`。上传必须带 `Content-Length`，分块传输返回 400（否则能绕过上限）。`/v1/checks` 仍是 1 MB、超限 400。
- 流水线新增第 0 步「预处理」：分析器接口加了 `has_prepare` / `prepare_budget_s()` / `prepare()`（默认什么都不做，向后兼容）。媒体那一路在这里取文件、OCR / 转写，把派生行（`line_id` 形如 `d0-1`，`speaker=unknown`，已脱敏）补进输入，话术、链接、案例三路都能看到；汇总的逐字回查用的是补过的输入，所以引用派生行的证据能通过回查，编造的引文照样被丢掉。派生行出现在 `GET /v1/checks/{id}` 的 `derived_lines` 里。
- 时间预算：预处理用 `MEDIA_PREPROCESS_BUDGET_S`（默认 6 秒），流水线再把它压到「整单截止 − 汇总预算 − 话术超时」之内，不挤占话术的 12 秒，整单 20 秒硬上限不变。到点放弃并取消预处理任务；超时或失败时媒体条目记 `not_analyzed`（「分析超时」），报告带 `deepfake_unavailable`，`run()` 不会再分析一遍，其余各路照常出报告。整单被取消（服务关闭）时预处理任务一起取消。
- 输入校验补了两条：客户端的 `line_id` 不能是 `d<数字>-<数字>`（留给派生行，避免证据指错行）；同一个 `media_id` 在一次请求里出现两次返回 400。媒体只能被一次鉴定认领，认领时记下真实的 `check_id`。
- 模拟模式：`POST /v1/media` 照样真实校验、保存并返回 201（Android 联调上传流程要用），鉴定仍返回固定的模拟报告，`derived_lines` 为空。模拟模式不建流水线，文件不会被分析，也不会被清理任务删除，留到 1 小时过期后由真实模式的清理任务清掉。
- `MEDIA_*` 配置项留在媒体包自己的 `MediaSettings`（前缀 `MEDIA_`），没有并进 `config.py`；`.env.example` 加了「媒体」一段。
- 顺带修掉的：权重清单里语音转写的 `used_by` 是 `asr`，运行时却按 `sensevoice` 找，真实进程里语音转写永远不可用（单元测试用假引擎没发现，端到端实测时发现）；`python -m app` 打印启动状态时建了一条流水线，把模型又加载了一遍、退出时还要等它加载完，现在打印状态时不预加载。
- 复审确认的三处缺陷（提交 48fe70e）：README 第 6 节把「任一路失败」都说成封顶 `suspicious`，改成只有主备大模型都不可用时封顶；`intel_unavailable` 的解释改成「配置了的情报接口没查成」；服务运行中跑的自检结果在服务关闭时被更早的真实调用结果覆盖，改成只在自己的结果更新时才写回，补了测试。
- 测试变慢（提交 fcd5c43）：装了 `media` 依赖组后每次起应用都在后台加载真实的 SenseVoice。自动生效的夹具设 `MEDIA_PRELOAD=0` 并清掉其他 `MEDIA_*` 环境变量，默认测试不加载真实模型。
- `probe.py` 直接用 Pillow，`media` 依赖组里补上显式声明（提交 916164d，只改 `pyproject.toml` 和 `uv.lock`）。
